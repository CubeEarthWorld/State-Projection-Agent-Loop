# ツール探索

既定の探索経路は「ジャンル → 短い説明 → 選んだツールの詳細」です。
`tool_search` 1個で探索します。常駐ツールは `read`、`bash`、`edit`、`write`、
`grep`、`find`、`ls` と `tool_search`、`peek`、`history_search`、`checklist` の11個です。
基本ツールの作業ディレクトリは `Session(workspace_root=...)` で指定します。

```text
tool_search(action="categories")
tool_search(action="list", category="research", k=8)
tool_search(action="describe", name="research.search")
```

- `categories`: ジャンルごとの総数・常駐数・未閲覧数・除外数を返します。
- `list`: 指定ジャンルとその子ジャンルの未閲覧ツールを名前順で返します。
  各カードは名前・ジャンル・短い説明・タグだけです。`category="*"` で全ジャンルを探索できます。
- `search`: 名前や自然文で未閲覧ツールを検索します。`query` が必要です。
  文字列検索・タグ・設定済みならベクトル検索を組み合わせます。
- `describe`: 指定した `name` の詳細仕様・注意点・使用例を取得し、そのツールだけを
  次回の native tools 入力へ追加します。以前のカードを再確認する用途でも使えます。
- `reject`: 不適切だった `name` と任意の `reason` を記録し、候補と native tools から外します。
  過去の会話に出た説明は履歴として残ります。常駐ツールは除外できません。
- `reset`: 閲覧・除外記録を明示的にリセットして再検討できるようにします。
  実行済み操作の取り消しや、全ツールのアンロードは行いません。

`action` の既定値は `categories` です。一覧・検索・詳細取得には明示的に
対応する `action` を指定します。旧ツール名の別名や旧探索方式への互換処理はありません。

## 再探索の保証

閲覧したツールは、最新のユーザー入力から始まる探索単位内で除外されます。
除外は検索語・ジャンルをまたいで共有されます。例えば親ジャンルを見た後で
子ジャンルや別の検索語へ移っても、同じバージョンのカードは重複しません。

同じ引数で新しい探索コマンドを呼ぶと、未閲覧の次のページを返します。
同じコマンドIDの再試行では元のページを返し、ページを飛ばしません。
候補が尽きた場合は空の一覧と、他ジャンルも含む残件数を返します。
LLMは残件数のあるジャンルを選びます。プログラムが無関係なジャンルを勝手に選ぶことはありません。
`has_more` は現在のジャンル／検索条件内の続きの有無です。

一覧経路は検索スコアに依存しないため、英語の定義も日本語の依頼からたどれます。
ジャンル選択と短い説明の理解は利用するLLMが担います。
名前・自然文検索で一致しなくても、ジャンル一覧経路から全登録ツールへ到達できます。
常駐ツールは既に仕様が入力されているため、カード一覧から省きます。

閲覧・除外・詳細取得は `tool_discovery` イベントとして台帳に記録します。
会話圧縮やプロセス再起動で記録は消えず、分岐・巻き戻しにも対応します。
新しいユーザー入力、または明示的な `reset` で新しい探索を始めます。
ツールのバージョンが上がると未閲覧として再表示されます。同一バージョンの定義変更は
再閲覧の対象にならないため、仕様変更時はバージョンを更新してください。
`tool_search` は探索状態への書き込みを宣言し、同じバッチの呼び出しも順番に実行します。
既定の安全ポリシーはこのローカルな状態変更を許可しますが、上位の拒否は維持されます。

## 任意のベクトル候補

`discovery.auto_candidates=False` が既定です。接続口は既存の `EmbeddingBackend` を使います。
明示的に有効化し、埋め込みバックエンドを設定した場合のみ、最新ユーザー入力のベクトルと
対象ツールのベクトルのコサイン類似度で上位候補を選びます。
バックエンドがない場合や `vector="off"` なら候補は出さず、文字検索へ代替しません。
多言語での意味照合には、それに対応した埋め込みモデルが必要です。

候補も短い説明だけで、`describe` まで詳細仕様を読み込みません。
閲覧・除外済みツールと常駐ツールは候補から省きます。
`no_embed=True` のツールはベクトル候補に含めず、ジャンル経路から到達できます。
今回の確認ではモデル接続・ベクトル生成・実際の意味検索の評価を実行していません。

## ローカル確認

外部サービスも埋め込みモデルも使わない確認コード:

```powershell
$env:PYTHONPATH = 'src;tests'
python tests/unit/test_tool_browsing.py
```

JSONツール定義とイベント契約が変わるため、別リポジトリのDart版も同期が必要です。
この変更はPython版だけです。
